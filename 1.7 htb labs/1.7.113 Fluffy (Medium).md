#ESC16   
ESC16 concerns a CA-wide configuration that omits the certificate security extension.

**ESC16: Privilege escalation through weak certificate mapping**
When an Active Directory Certificate Services (AD CS) certification authority omits the SID security extension, a domain controller that permits weak certificate mapping may rely on the certificate’s User Principal Name (UPN) to identify the account. If an attacker can modify an account’s UPN and that account can enroll for a client authentication certificate, the resulting certificate may authenticate as a more privileged user.

Weak certificate identity mapping allowed a certificate requested by one principal to authenticate as a more privileged principal.
```bash
# Privileged certificate identity mapping assessment
certipy-ad account -u winrm_svc@fluffy.htb -hashes 33bd09dcd697600edf6b3a7af4875767 -user ca_svc -upn administrator update -dc-host DC01.fluffy.htb -dc-ip 10.129.50.60

# Verify the directory attribute state
certipy-ad account -u winrm_svc@fluffy.htb -hashes 33bd09dcd697600edf6b3a7af4875767 -user ca_svc read -dc-host DC01.fluffy.htb -dc-ip 10.129.50.60
```

#### Recap
The initial credentials provided access to an IT share. A notice pointed to CVE-2025-24071, and the vulnerability exposed another user's authentication material. BloodHound revealed delegated group and account permissions that exposed several service accounts. Access as winrm_svc yielded the user flag.

The CA's ESC16 configuration allowed weak certificate mapping to a privileged identity. The resulting administrator access yielded the root flag.

Key Concepts:
1.  CVE-2025-24071 can expose outbound Windows authentication when affected archive content is processed.
2. Audit GenericAll and GenericWrite in Active Directory, especially when the target is a privileged group or a service account.
3. Require strong certificate binding and audit CA-wide settings that suppress the security extension.
