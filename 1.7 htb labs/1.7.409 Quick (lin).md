#ESI  #esi
Edge Side Includes (ESI) let a reverse proxy or cache assemble portions of a response.

If untrusted content reaches the ESI interpreter, it can cause the intermediary to fetch attacker-influenced resources.

The environment also processed XSLT. The combination turned unintended resource loading into a potential code execution path.

#### Recap
UDP port 443 exposed a QUIC service and documentation containing an initial credential. The ticketing application passed user-controlled data into ESI processing, and its XSLT environment allowed unsafe extension calls. The combined exposure yielded initial access.

I assessed two privilege escalation paths.
Path one: PwnKit exposure in the SUID pkexec binary led to root access.
Path two: weak database password storage exposed a printer administration credential. The printer workflow trusted a writable spool directory, exposing privileged file reads through symbolic links.
```bash
while true; do for fn in *; do if [[ -r $fn ]]; then rm -f $fn; ln -s /home/srvadm/.ssh/id_rsa $fn; fi; done; done
```
The spool-file flaw exposed the printer service account's SSH key. The associated account could access printer configuration containing the root password, which led to root access and the root flag.

Key Concepts:
1. Do not interpret untrusted response content as ESI directives.
2. Disable unsafe extension functions when running untrusted XSLT.
3. Identify the algorithm and salt handling used by PHP crypt before assessing stored hashes.
4. Use safe file handling in privileged spoolers to prevent symbolic link races.
