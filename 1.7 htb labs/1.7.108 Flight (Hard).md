#### Recap

An additional virtual host was vulnerable to local file inclusion, which exposed outbound service-account authentication. Password reuse and a writable shared directory led to another user's credential exposure. That user could modify web application content, which led to initial shell access and the user flag.

A nonpublic IIS site on port 8000 supported ASP.NET and accepted changes to its application content. The resulting application pool identity held SeImpersonatePrivilege, which led to SYSTEM access. An alternative Kerberos-based approach did not succeed.


Key Concepts:
1. Writable shares can expose users to files that trigger outbound authentication.
2. Password reuse can extend the impact of a compromised low-privilege account.
3. Services bound to internal interfaces still matter when evaluating host exposure.
4. Confirm which server-side runtimes are enabled when assessing an IIS site.
