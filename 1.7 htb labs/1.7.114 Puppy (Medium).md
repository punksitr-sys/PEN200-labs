#### Recap
The lab's initial credentials allowed a BloodHound review that identified three relevant delegations.
1.  The initial account inherited GenericWrite over DEVELOPERS through HR.
2. A DEVELOPERS member also belonged to SENIOR DEVS, which held GenericAll over adam.silver.
3. The adam.silver account belonged to Remote Management Users.
The DEVELOPERS delegation exposed the DEV share and a KeePass vault. The first recovery tool did not support the vault's KDBX format.
```bash
sudo apt install snapd
sudo systemctl start snapd.service snapd.socket
sudo snap install john-the-ripper

snap run john-the-ripper.keepass 2 john recovery.kdbx | tee recovery.kdbx.hash
snap run john-the-ripper recovery.kdbx.hash --wordlist=rockyou.txt
```
The vault exposed a SENIOR DEVS credential. The group's GenericAll rights over adam.silver ultimately led to WinRM access and the user flag.

A site backup exposed credentials for steph.cooper.
```powershell
Expand-Archive -Path C:\Backups\site-backup-2024-12-30.zip -DestinationPath C:\Users\adam.silver\Documents -Force
```
WinPEAS identified a DPAPI credential file in the account profile. The saved administrator credential was recoverable in that context, leading to administrator access and the root flag.

Key Concepts:
1. Verify KDBX format compatibility when evaluating a KeePass vault's password strength.
2. PowerShell's Expand-Archive extracts ZIP archives.
3. Treat DPAPI credential files and their associated key material as sensitive.
