#### Recap
The initial investigation yielded one useful hint and identified Jen as a possible account.
```txt
Hey Jen, just installed wordpress over at wp.gitroot.vuln
please go check it out! 
```
The WordPress virtual host contained mostly unrelated material.
Discovering additional virtual hosts was the main breakthrough.

The repository virtual host exposed a Git directory.
The recovered repository contained a user record for Pablo.
```txt
33513a92c025212dd3ab564ca8682e2675f2f99bba5a7f521453d1deae7902aa.txt
pablo_S3cret_P@ss
beth_S3cret_P@ss
jen_S3cret_P@ss

pablo_HELP.txt
I need help, something is wrong with this git repo
```

The SSH assessment eventually found that Pablo's password matched the account name.

 SSH access as Pablo yielded the first flag. I then reviewed local privilege boundaries.
 A search for local text files found message.txt, which contained the next clue.
 ```txt
Hey pablo

Make sure to check-out our brand new git repo!
 ```
The references to a checkout and a new repository led to a second Git repository under /opt/auth.
Of roughly 200 branches, dev-43 stood out in size. Its history exposed Beth's password.

I reviewed the host again under Beth's account.
A file named addToMyRepo.txt provided the next lead.
```txt
Hello Beth

If you want to commit to my repository you can add a zip file to ~jen/public/repos/ and ill unzip it and add it to my repository

Thanks!
```
A repository submission workflow unpacked archives in a directory associated with Jen. It trusted repository hook content, allowing execution under Jen's account.

I had access as Jen but initially lacked the password needed for sudo. An editor history file exposed a candidate.
```txt
# Search String History (newest to oldest):
?/binzpbeocnexoe
|2,1,1590471908,47,"binzpbeocnexoe"
```
The candidate authenticated as Jen. A sudo rule allowed privileged Git operations, and its pager behavior led to root access and the second flag.
