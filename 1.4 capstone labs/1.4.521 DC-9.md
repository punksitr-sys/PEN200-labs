#### Recap
The HTTP application exposed SQL injection and administrator credential data. Authenticated file inclusion then exposed system usernames and the configuration that gated SSH access.
Several credentials worked over SSH. A file in the Janitor account exposed an additional password that provided access as Fred, who could read the first flag and invoke a privileged helper.

The sudo-authorized helper could append data to a protected account file, yielding root access and the second flag.

Port knocking changes firewall access in response to a configured sequence of connection attempts. This explains why the initial scan showed only HTTP.
```bash
# The first port-knocking test did not open SSH
knock 192.168.236.209 7469 8475 9842
# The alternate test confirmed SSH reachability
sudo nmap -p 7469,8475,9842 -r -sS --scan-delay 200ms 192.168.129.209
```

Linux password databases can contain several crypt formats. Assess the hash identifier rather than assuming the default.
```bash
MD5-crypt hashes use the $1$ prefix
SHA-256-crypt hashes use the $5$ prefix
```
