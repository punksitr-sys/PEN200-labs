#### Recap
The host exposed FTP, SSH, and HTTP on ports 21, 22, and 80.
Anonymous FTP access revealed an empty, writable pub directory.
Directory discovery found robots.txt, which contained the following hint.
```txt
You are not a search engine! You can't read my robots.txt! 
```
Comparing requests under different user-agent identities revealed a hidden directory.
```txt
User-agent: *
Disallow: /secret_information/
```
Local file inclusion could reach the FTP upload directory. The application evaluated attacker-controlled PHP from that directory.
```txt
http://192.168.247.14/secret_information/?lang=/var/ftp/pub/exp.php
```
The resulting shell ran as www-data and yielded the first flag.

The SUID inventory included pkexec, but I focused on the lab-specific helper.
The SUID rootshell binary was accompanied by readable C source. I reviewed how it checked the caller's identity.
```c
cat rootshell.c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <string.h>

int main() {

    printf("checking if you are tom...\n");
    FILE* f = popen("whoami", "r");

    char user[80];
    fgets(user, 80, f);

    printf("you are: %s\n", user);
    //printf("your euid is: %i\n", geteuid());

    if (strncmp(user, "tom", 3) == 0) {
        printf("access granted.\n");
        setuid(geteuid());
        execlp("sh", "sh", (char *) 0);
    }
}
```
The helper invoked an identity command without an absolute path, making its result dependent on PATH.
- The caller could influence which executable the helper resolved.
- The helper used the external command's output in its authorization decision.
Trying to start a shell directly through the replacement command failed. The useful issue was the helper's trust in the returned identity string.
The subsequent test confirmed that the identity check could be fooled and that the helper could open a root shell.

Relevant behavior in the C source
popen() starts the specified command through a shell and returns a stream from which the parent can read its output.
fgets() reads command output through the stream into the fixed-size user buffer.
The comparison checks only the first three characters against the expected user name.
setuid(geteuid()) aligns the process identity with its effective UID. The SUID root binary started with effective UID 0.
execlp() replaces the current process with a shell found through PATH. Its argument list ends with a null pointer.
