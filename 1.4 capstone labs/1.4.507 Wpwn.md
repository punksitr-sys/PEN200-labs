```bash
wpscan --url http://ip/wordpress/wp-login.php -U admin -P /usr/share/wordlists/rockyou.txt --no-update
```
The first 3,000 password candidates did not yield a valid credential.
I reviewed the installed WordPress plugins.
```bash
wpscan --url http://ip/wordpress --enumerate vp --plugins-detection aggressive --no-update
```
The plugin-only scan was slow and found no useful result.
A default scan identified the Social Warfare plugin.

#### Recap
Port and directory discovery identified WordPress, but the initial password assessment did not yield a valid credential.
The narrow plugin scan missed the installed plugin. The broader inventory found it.
```bash
wpscan --url http://ip/wordpress --enumerate vp --plugins-detection aggressive --no-update
# The vulnerability-only plugin scan returned no plugins

wpscan --url http://ip/wordpress --enumerate p --plugins-detection aggressive --no-update
# akismet
# social-warfare
# [!] The version is out of date, the latest version is 4.5.6
# [!] Directory listing is enabled

wpscan --url http://ip/wordpress --no-update
# social-warfare
```
The vulnerable Social Warfare plugin led to execution as www-data. WordPress configuration exposed a database password that was reused by Takis. The database and SUID checks yielded no additional leads, but Takis had unrestricted passwordless sudo and could read the root flag.
