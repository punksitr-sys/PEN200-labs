#### Recap
This was my first standalone 30-point lab. The platform rated it Hard, and the community rated it Very Hard.

Public employee names and weak seasonal passwords exposed a domain credential. Service ticket exposure then identified weak protection on a SQL service account.
The SQL account opened an SMB share containing a password-reset utility. Static analysis revealed a help desk credential. BloodHound showed that the help desk delegation affected an account with WinRM access.

The internal SQL Server listener trusted tickets based on the exposed service account key. The resulting privileged database context provided execution under the SQL Server service identity.
The service token and running spooler exposed a local elevation path that provided administrator-equivalent access.

Key Concepts:
1. Review service account password strength and SPN exposure.
2. Use Ghidra to examine embedded strings and control flow in Windows binaries.
3. Use BloodHound queries to identify the intersection of delegated rights and remote access.
4. Audit RPC-accessible password reset delegations.
5. Protect Kerberos service keys from exposure to prevent forged service tickets.
6. Review Kerberos trust and role assignments on SQL Server.
7. Restrict SQL Server features that execute operating-system commands.
