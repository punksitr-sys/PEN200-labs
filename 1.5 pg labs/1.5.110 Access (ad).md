#### Recap
The lab combined web application exposure, Kerberos service account risk, and Windows local privilege escalation. The account switch remained the least reproducible part.
Unsafe upload handling led to initial code execution as the low-privilege web account. Directory enumeration exposed a SQL Server service principal, and its weak Kerberos service account credential led to access as the SQL service identity.

>The alternate logon method failed repeatedly, worked once, and could not be reproduced consistently. The cause remained unresolved.

The SQL service account held SeManageVolumePrivilege, which exposed writes to protected locations on the system volume. A WMI DLL loading path led to NETWORK SERVICE. The enabled impersonation privilege then led to SYSTEM access.

>The DLL path yielded NETWORK SERVICE rather than SYSTEM directly. Further investigation was limited by the unreliable switch to the SQL service account.
